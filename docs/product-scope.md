# DayCue 第一阶段：产品范围

本文件定义**本轮实际交付**的范围。整体产品设计见根目录 `proactive-assistant-design.md`。

## 1. 第一阶段的唯一目标

让一名大学生能在路上用一句话记下一件事，并且在设备上看到它变成**真实存在的提醒**——包括明确知道它到底写没写进苹果提醒事项。

成功标准沿用设计文档：**少漏事、少操作、少打扰**。

## 2. 做什么

| 能力 | 本轮范围 |
|---|---|
| 捕获 | 文字直接提交；按住录音（显式开始/结束）；拍照或选图 + Vision OCR，识别结果可编辑 |
| 整理 | 后端把一段话拆成「笔记 + 若干任务」，每条带原文依据与时间表达 |
| 时间 | 相对日期、明确月日、星期、跨午夜、缺年份、DST 全部按录入时刻与用户时区确定性解析 |
| 澄清 | 时间不明确、地点多义、模型编造依据、日期落在过去 → 标记歧义，交给用户确认 |
| 任务 | App 内任务 + 苹果提醒事项写入；选清单；标题/备注/截止日/提醒时刻/完成状态 |
| 状态 | 已保存到 App / 等待写入 / 已写入 / 写入失败 四态真实显示；撤销入口 |
| 离线 | 捕获先落本地；解析失败保留记录并可重试；权限被拒任务不丢 |
| 记忆页 | 空状态，说明本阶段不做推断式记忆 |
| 设置 | 默认清单、四项权限状态、AI 服务地址（Token 存 Keychain）、自动创建开关、本地数据管理 |

## 3. 明确不做（以及原因）

| 不做 | 原因 |
|---|---|
| 云端存储用户任务 | 第一阶段后端无状态，用户数据只留在设备上 |
| 模型直接调用 EventKit | 权限必须由程序验证，模型只产出候选 |
| 替用户编造提醒时刻 | 「周五之前」只产生截止日 |
| 自动把课堂内容变成提醒 | 笔记与行动任务必须分开；只有行动意图才是任务 |
| 伪造语音识别结果 | 识别失败就显示失败；模拟模式直接拒绝转写 |
| 全天录音、持续定位 | 与设计文档的限制一致，且第一阶段无位置功能 |
| 课表、课后追问、长期记忆 | 第二、三阶段；本轮只留接口位置 |
| 账号、云同步、Android | 第四阶段 |

## 4. 现实约束（写进产品承诺，不藏起来）

1. 苹果提醒事项的读写只在设备上经 EventKit 完成，服务器不参与。
2. 本轮**没有** Android 端，也没有 iPhone 桥接。
3. 后端未配置供应商时，整理功能不可用；客户端显示「AI 未配置」而不是猜。
4. 模拟模式下的结果是预设样例，界面上必须标注「模拟结果」。
5. iOS 端代码在无 Xcode 的环境中编写，**尚未编译、尚未真机验证**（详见 [phase-1-acceptance.md](phase-1-acceptance.md)）。

## 5. 本轮采用的默认值（可调整的假设）

| 项 | 取值 | 理由 |
|---|---|---|
| 最低 iOS | 17 | 设计文档建议；`requestFullAccessToReminders` 等 API 从 17 起可用 |
| 后端默认地址 | `http://127.0.0.1:8787` | 本地开发；改非环回地址强制要求令牌 |
| 默认执行策略 | 先预览再确认 | 设计文档：初次使用默认结果预览 |
| 有明确时刻时 | 截止与提醒同一时刻 | 用户说了「八点提醒我」，这就是提醒时刻；可在预览页改 |
| 只有日期时 | 只设截止日 | 不编造时刻 |
| 音频格式 | m4a | iOS 原生，体积小 |
| 服务端最大 JSON | 256 KB | 单次随手记录的合理上限 |
| 服务端最大音频 | 12 MB | 约数分钟 m4a |
| 清理策略 | 本轮不自动删除任何本地数据 | 避免误删；删除入口留给用户显式操作 |

## 6. 第二阶段的接口预留

不在本轮实现，但已经预留位置：

- `ScheduleSeries` / `ScheduleOccurrence` 已出现在设计文档的数据模型里，本轮不建表。
- `ProactiveCandidate` / `DeliveryPlan` 同上。
- 契约里的 `client_context.has_course_schedule` 已经存在，第二阶段课表接入时直接可用。
- `memory_item` 表已建但只读空值，第三阶段写入。

刻意**不**做的事：不为这些功能提前写空类、假接口或引入依赖。

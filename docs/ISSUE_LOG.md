### ISSUE-20261029-002｜悬浮球「是否在运行」只有进程内静态标记
- **首次发现 / 最近更新**：2026-10-29 / 2026-10-29
- **模块与环境**：`platform/overlay/FloatingBallService.kt`（`companion object.isRunning`）
- **严重程度**：P3 低
- **状态**：已知限制
- **现象、预期、实际**：预期能准确回答「现在有没有球挂在屏幕上」；实际只能依赖服务生命周期里维护的静态布尔值——进程被系统整体杀掉（不是 onDestroy）时该标记会随进程一起消失，但若服务被系统回收而进程仍存活，标记与真实窗口状态理论上可能短暂不一致
- **复现步骤与条件**：仅在一个「进程存活但服务被系统回收」的时序窗口内可见，本机无设备未能构造
- **原始证据（已脱敏）**：无（未复现，标记为「待定位」的真实成因）
- **影响范围**：设置页「当前状态」一行的显示；不影响球本身
- **根因与定位依据**：Android 没有公开 API 查询「本进程是否持有 SYSTEM_ALERT_WINDOW 窗口」；ViewModel/服务状态只能自报
- **解决方案及实际变更**：保留静态标记，并在设置页把「开关状态」与「运行状态」分开显示；回前台时若开关开着而标记为未运行则补启一次（自愈）
- **回归测试位置 / 测试 ID**：人工——杀进程/等待系统回收后回到 App，看设置页状态与球是否恢复

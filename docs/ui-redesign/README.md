# DayCue Android 界面重构（视觉 / 信息层级 / 日常操作）

本次只改界面层：主题与组件、四个主页面与设置二级页、底栏与状态栏处理。
业务逻辑、数据库、权限与服务调用都没有改，也没有新增产品功能。

## 1. 设计语言（先立规矩，再改页面）

| 维度 | 做法 | 落点 |
| --- | --- | --- |
| 强调色 | 统一低饱和青绿（浅色 `#2E6B5C` / 深色 `#8FD3C0`），去掉原来的浅紫按钮 + 绿色导航混用 | `ui/theme/Color.kt` |
| 底色 | 浅色用暖白 `#F7F6F1`，深色用近黑 `#101413`，不再是纯白/纯黑 | 同上 |
| 字体 | 全部系统 sans-serif，中文字号最小 12sp、正文 15–16sp；行高按 1.4 倍给足 | `ui/theme/Type.kt` |
| 间距 | 页面左右 20dp，区块间距 24dp，行内 12–16dp | `ui/theme/Dimens.kt` |
| 圆角 | 8 / 10 / 14 / 20 / 28dp 五档，卡片 20dp，行 14dp | `ui/theme/Shape.kt` |
| 触控 | 所有可点区域 ≥ 48dp，列表行 ≥ 56dp | `MinTouchTarget` / `MinListRowHeight` |
| 组件 | 外壳、分区标题、按钮（4 档）、列表行、状态行、输入、标签、空态、提示各一份 | `ui/common/Components.kt` |

**关于手写字体**：截图里那套手写体不是 App 提供的。同一台设备上状态栏时间、通知、系统设置页文字都是手写体——这台机器把系统字体换成了手写体。App 侧没有任何内置字体文件，`Type.kt` 用的是 `FontFamily.SansSerif`，所以随系统字体变化是预期行为，也没有引入无法确认授权的中文字体包。

## 2. 四个页面的改动（都是「取舍」而不是换皮）

### 今天页
- 顶部压成一条紧凑页头：问候 + 日期（`10月26日 周一 · 20:36`）+ 强刷 + 设置入口。
- 首屏第一块是「记一句」：语音做成 56dp 圆形主按钮，文字、拍照并排在下面；它们和记录页共用同一个录入流程（`capture?intent=voice|text|image`），没有第二套逻辑。
- 只有真有内容时才铺分区，顺序按重要性：接下来（课）→ 今天到期（待办）→ 等你回复（追问）→ 今天记下的。全空时只给一句引导加三个快捷入口，不再六块空态堆叠。
- 同步异常压成一行提示（`2 项同步没有完成 · 查看`），点进去才看具体哪几条；「2 条记录还在处理」同理。
- 删掉了「今天页只做汇总，不做任何写入」这类实现说明。待办时间改成当天只写时刻：`22:00 截止 · 21:30 提醒`。

### 记录页
- 空态以「说一句」为主操作，文字/拍照并排；搜索框和筛选**只在有记录时才出现**，搜索不再是视觉焦点。
- 有记录时每行只保留：来源标签 + 时间 + 标题 + 摘要（必要时 `已修订`），没有进程或技术过程说明。
- 筛选维度按来源（全部 / 记录 / 课后回复 / 手动创建），筛选只影响展示，不改列表本身。

### 记忆页
- `需要你看一眼` / `待确认` / `存在冲突` / `已确认` / `已失效`（默认折叠）分区；顺手修掉了旧版「同一条既在需要你看一眼、又在待确认里出现两次」的问题。
- 来源说明放详情/帮助弹窗（右上角 ⓘ → 「记忆怎么来的」），不占主区。
- 文案纠正：用户陈述记的是「你的说法，不代表它一定成立」，推断只能作候选。

### 设置页
- 首页是分组列表（8 组）：账号与同步 / 通知与主动帮助 / 地点与规则 / 课表与学期 / 权限 / 外观 / 数据管理 / 高级设置，每行带一句真实状态摘要。
- 服务地址、Bearer Token、连接诊断全部下放到「高级设置」，日常首页不再出现地址输入框。
- 权限页只显示每项能力的「已授予/未授予 + 被拒绝时会怎样」，跳系统设置由按钮完成。
- 数据管理里的危险操作单独成组，带二次确认。
- 新增「外观」：跟随系统 / 浅色 / 深色，偏好存 `app_setting`（`ui.theme_mode`），属于界面偏好不是新功能。

### 底栏与系统栏
- 四个入口统一线性图标 + 文字（今天/记录/记忆/设置），去掉了「用单个汉字当图标」；选中态用青色容器 + 图标着色。
- `记忆` 图标是自绘书签线框（material-icons-core 里 Star 是实心星，混在线框里不协调），`麦克风/相机` 也是自绘，避免引入 material-icons-extended。
- 边到边显示，状态栏/导航栏图标颜色随深浅色切换，窗口底色与 Compose 背景一致（冷启动不再白闪）。

## 3. 第二轮真机迭代（在真机上一屏一屏改的）

第一轮把结构和配色立住了，第二轮是拿真机截图逐页找毛病、改完再截图核对的。改的都是排版本身，没动业务逻辑。

| 位置 | 原来 | 现在 | 为什么改 |
| --- | --- | --- | --- |
| 今天页 页头 | 顶部留白 24dp，问候与日期之间松 | 去掉顶部额外留白，日期紧贴问候 | 首屏要尽快出现「记一句」，不是标题 |
| 今天页 空态 | 一整段长句顶在左边缘 | 「今天还没有安排」+ 一句说明，限宽 270dp 居中 | 长句在左边缘、大字号下折三四行，像没排完版 |
| 今天页 快捷入口 | 三个文字块贴在左侧 | 三个等宽块 + 图标（课表/待办/追问），细描边 | 看不出是三个并列入口，也不知道点进去是什么 |
| 今天页 课程卡 | 名称 / 时间 / 地点三行 | 名称一行，时间用主色 + 「·」地点同一行 | 「几点、在哪」是最常确认的信息，不该分两行扫 |
| 记录页 空态 | 三个按钮宽度不一，整体贴在顶部 | 整块在视口 78% 高度内居中；说一句占满、下面两个等分 | 顶部留白像「还有内容没加载出来」；按钮不等宽像随手摆的 |
| 记录页 列表 | 箭头居中悬在整块右侧 | 箭头跟标题同一行 | 正文变长时箭头浮在第二行，看不出属于哪行 |
| 记录页 搜索/筛选 | 搜索框整块偏亮；选中标签只是浅一档 | 搜索框底色降一档；选中标签用主色实底 | 扫描时一眼能看出当前筛选，搜索块不再压住列表 |
| 记忆页 | 每条记忆浮在页面上，操作按钮撑成一条按钮带 | 同一状态一组圆角容器 + 行间细线；操作按钮收成一行小字 | 原来十条记忆像十段散落的文字，分不清组 |
| 记忆页 标签 | 「推断」用错误红，和真正的冲突同色 | 推断 → 中性灰；待复核 → 主色 | 红在别的页面专指「出问题了」，推断不是错误 |
| 权限页 | 状态另起一行藏在说明下面 | 状态做成右侧标签，动作跟在标签下 | 五项排下来要读到第三行才知道哪几项没给 |
| 记一笔 | 三个入口挤一行且宽度随文字变；保存缩在左下 | 录音独占一行，拍照/选图下面等分；保存占满整行 | 系统字号 1.3 倍时「录音」会被折成两行；保存是唯一提交动作 |
| 筛选标签行 | 普通 Row | 可横向滚动 + 单行不换行 | **真机 1.3 倍字号下「手动创建」被压成竖排单字** |
| 账号页 | 令牌状态写「未保存：设备登记与解析会返回 401」 | 标签只写「未保存」，401 后果移到说明行 | 长句塞进标签会挤掉左边的名称 |

**这一轮还发现并修掉了一个真实缺陷**：调试期间 App 的「外观」被设成了「浅色」，于是系统切深色后界面不跟着变——正好验证了「外观」这个偏好是生效的；已经改回「跟随系统」。

## 4. 第三轮：从「排好了」到「读得顺」

第二轮解决的是「一屏里谁该更显眼」，这一轮解决的是「日常用起来顺不顺手」。判断标准换成了三个具体的用户问题：
**我知道这条是什么时候的吗？我一眼看得出该点哪个吗？这页是空的还是出问题了？**

| 位置 | 改动 | 用户在解决什么问题 |
| --- | --- | --- |
| 记录行 | 只有 `19:30` → `今天 19:30` / `昨天 21:10` / `10月20日 08:05`（跨年补年份） | 隔天的记录和刚写的一模一样，只能靠记忆回推日期 |
| 记录行 | 标题提到 17sp，正文降到次级色并限两行 | 三行一条的记录里标题和正文同字号，整块糊成一段 |
| 记录列表 | 行间加发丝线 | 连续多行文字没有分隔，扫描时找不到边界 |
| 记忆行 | 日期从 `2026-10-20` 改成 `10月20日` | ISO 串是给机器看的，混在中文界面里像调试信息 |
| 记忆行 | 确认＝主色、作废＝中性、删除＝错误色 | 三个按钮同色时，得先读完三个词才知道该点哪个 |
| 课程卡 | 时间右侧加 `进行中` / `40 分钟后` / `2 小时后` | 用户要的是「离现在还有多久」，不是 `19:00` 这个数字 |
| 等你回复 | 整行可点 + 右侧箭头 | 原来只有页头「去回复」能点，行本身看着像纯文字 |
| 三个空态 | 加一枚主色圆底图标（日历 / 列表 / 书签） | 「空」和「出错」长得一样；图标先把「这里本来做什么」说出来 |
| 今天页快记 | 写文字 / 拍一张 等宽 | 宽度跟着文字长度走的一排按钮看着像没对齐过 |
| 列表增删 | `animateItem` 平滑让位 | 勾掉一条待办时整块瞬移，像页面重载了一次 |
| 文案 | 「文字、录音、照片都先存到本机」→「说一句、写几个字，或拍一页板书」；「再尝试解析」→「之后自动整理」 | 原句在讲实现，用户在讲他要做什么 |

**日期显示的两套规则（有意为之，不是不一致）**：列表用相对日期（今天 / 昨天 / 10月20日），因为列表是「翻」的，相对日期帮助定位；详情页和课表用绝对日期（2026-10-26 19:30），因为那里是在核对具体某一条，需要能直接抄下来。

这一轮补了两条单测钉住时间语义：`listTimeUsesRelativeDayThenDate`、`minutesBetweenIsSigned`（课程卡的「40 分钟后」直接来自这个差值，正负号不能反）。

## 5. 第四轮：详情页、疏密与"点下去之后"

前三轮都在讲"看到什么"，这一轮补三件事：**详情页怎么读、一页里卡片该有几张、点下去之后有没有回应。**

**1）记录详情页：从"表单"改成"先读后改"**

| 原来 | 现在 | 为什么 |
| --- | --- | --- |
| 两个带 label 的描边输入框 + 两个按钮 | 标题与正文是无边框编辑区（聚焦才露出输入线） | 用户多数时候只是想看一眼这条记录，一进页面像表单会误以为必须填 |
| 「保存修订」「删除」并排两个按钮，未改动时按钮灰着 | 未改动只显示一行小字「没有改动」，删除是右侧红色小字 | 灰按钮既占地方又让人怀疑坏了；删除是低频不可撤销动作，不该跟主操作抢位置 |
| 来源信息一行行裸着，「没有关联的待办」占掉整块空态 | 来源键值进分组容器（行间细线），来源原文做成左竖线引用块，空列表用一句话小字 | 详情页要能一眼分清"这条笔记"和"它的来源"；常态为空的区块不值得占半屏 |
| 截止时间写 `2026-10-26 22:00` | `今天 22:00` / `明天 09:00` / `10月20日 08:05` | 与列表页同一套日期写法，同一页不出现两种日期格式 |
| 顶栏「保存」与页内「保存修订」两个入口 | 只留页内主按钮 | 同一个动作两个入口，用户会犹豫该点哪个 |

**2）今天页的疏密：一页只有一张"卡"**

课程卡（进行中的时候）给一层极淡的主色底 + 淡主色描边，其余分区（待办、追问、记录）保持裸行。理由：这一页只有"现在正在发生什么"值得用容器强调，全都套卡片就等于都没强调。待办行的上下内边距从 4dp 加到 8dp——两行待办的复选框原来几乎贴在一起。

**3）点下去之后：三段反馈**

勾选待办不再是"点一下，行消失"：勾上（复选框打钩）→ 划掉（标题加删除线、整行降到 40% 透明度，220ms）→ 420ms 后提交，由列表的 `animateItem` 淡出收起。如果写库失败导致这一条没有被移除，1.2 秒后自动复位，不会永远停在划掉的样子。中间帧见 `23-task-completing-light.png`。

这一轮还给调试画廊加了 `note_detail` 场景（真机上要先录音、等识别才有一条笔记，凑不出来），详情页也因此拆成了 `NoteDetailScreen`（接 ViewModel）+ `NoteDetailContent`（纯展示），和另外三页一致。

## 6. 第五轮：数据库里有的，界面上就该看得见

从真机反馈查出来的一件事：**记一笔里拍了照、选了图，保存之后界面上只剩一句「已保存」，然后这条记录就再也找不到了。**

原因不是没存下来——`capture_item` 表和 `files/daycue/media/` 里都有；真正的原因是这条链路只走了半截：

| 环节 | 原来的行为 |
| --- | --- |
| 保存 | `saveImage` 写库 + 落文件，只把**文件名**拼进一句提示 |
| 界面状态 | 图片路径根本没进 `CaptureUiState`，没有任何地方渲染它 |
| 之后 | 图片没有 OCR 文本 → 不生成笔记 → 记录页只列笔记 → 一条都看不到 |

于是「已保存」只是一句话，既证明不了文件在，也证明不了保存的是你选的那张。文字记录也一样：解析失败或后端没配时，它同样只是一条 `capture_item`，在记录页里看不见。

**改法：界面上「本机记录」这一层，直接照着数据库列。**

1. 记录页新增「本机记录」分区。数据源就是本机 `capture_item`（`media_path` / `kind` / `status` / `recorded_at`），筛选条件是 **还没变成笔记**（`status != extracted`）——已经长成笔记的记录不重复列，避免同一件事出现两次。图片给 56dp 缩略图，录音和文字给同样尺寸的图标块，行高一致。
2. 点一行打开大图（`ContentScale.Fit`，确认「是不是这张」时不能裁）＋「删除这条」。删除先删库，再检查是否还有别的记录引用同一个文件：图片是按内容哈希去重的，同一张图选两次共用一个文件，直接删文件会把另一条记录变成裂图。
3. 记一笔里保存图片后立刻显示缩略图＋「换一张」「删除这张」；「换一张」会先撤掉上一张，不再堆重复记录。
4. 缩略图不引 Coil/Glide：`BitmapFactory` 先读尺寸再按 2 的幂采样，用不到图片库，也不会把 4000×3000 的原图整张解进内存（约 48MB，低端机直接 OOM）。

顺手修掉的：搜索框和来源筛选只在**有笔记**时才出现。之前只要有记录就显示，而搜索搜的是笔记的文字，图片参与不了——摆一个搜不到东西的搜索框是在骗用户。

诚实边界：图片没有接入 OCR、录音没有播放器，所以这些记录如实停在「已保存到本机」，点开只有大图和信息，没有文字可编辑。要让它们变成笔记，仍然需要后端解析。

## 7. 第六轮：把本机能做的接上（图片认字、录音回放）

上一轮把「数据库里有的」显示出来了，但记录本身还是空的：图片没有文字、录音没有声音。这一轮把**本机能做的两件事**接上。

**图片文字识别（离线）**

- 依赖 `com.google.mlkit:text-recognition-chinese`。选中文模型的两个理由：中文模型是**随 APK 打包**的版本（不是 Play Services 动态下载的那版），装好就能用，第一次识别不用等下载；拍照记板书经常发生在没网的教室里。
- 保存图片后立刻在本机识别，结果写进 `capture_item.ocr_text`，随后自动出现在记录页那一行的第二行、以及点开的大图下面。
- 界面上如实分三段：识别中 → 认出 N 个字 → 没认出文字（图片照样存着）。**不猜**：没识别到就写没识别到，不编内容。
- 三处限制：识别结果在记一笔里只显示前 4 行（整段铺开会把「换一张/删除这张」顶出屏幕），全文在记录页的大图预览里可以滚动查看。

**录音回放**

- 用 `MediaPlayer`（不是为了一个播放条引 ExoPlayer）：播放/暂停、`0:03 / 0:08` 进度、线性进度条，离开页面立刻 `release()`。
- 出现在两处：记一笔里「刚录的 N 秒」的卡片（旁边是「删除这段录音」），以及记录页里点开任意一条录音记录。

**代价与边界（说清楚）**

| 项 | 现在的状态 |
| --- | --- |
| 图片认字 | 本机完成，离线可用 |
| 录音回放 | 本机完成 |
| 录音转文字 | **仍需后端**。没配后端时如实报「转写失败：网络不可用或请求超时，内容已保存在本机」 |
| 结构化解析（哪句是待办、几点截止） | **仍需后端**。OCR 之后不会自动生成本地笔记，避免把识别噪声当事实写进库 |
| APK 体积 | 从 11.95 MB 涨到 54.85 MB，全是随包的识别模型。若要小包，可换成 Play Services 版（首次使用下载模型），但国内设备未必有 GMS |

## 8. 第七轮：输入闭环（认字 → 核对 → 保存笔记 / 提取待办 → 确认页）

这一轮把「记一笔」从「存下来」补成「存下来 → 用户核对 → 才变成笔记或待办」。

**文案：四种识别状态分开说**

| 状态 | 界面文案 |
| --- | --- |
| 识别中 | 正在识别上面的文字… |
| 认出文字 | 识别到的文字（N 字）+ 前 4 行 +「全文可在「记录」页点开这条查看」 |
| 图上没字 | 未识别到文字，图片已保存。 |
| 识别本身失败 | 识别文字失败，图片已保存。 |

「没字」和「失败」是两件事，之前合成一句「没认出文字」等于把两种情况混着说。

**三个动作（只在认出文字后出现）**

- **复制文字**：整段进剪贴板，提示复制了多少字。
- **编辑文字**：弹出的编辑框直接改识别结果，保存后走 `applyUserEdit`（置 `user_edited`），晚到的机器结果不能覆盖用户改过的内容。
- **保存为笔记**：先弹确认框——标题默认取**首个非空行并截到 40 字**、正文默认是识别全文，两者都能改；**点「保存笔记」才写 note 表**。笔记带 `origin_capture_id` 指回这张图，纯离线完成，不写长期记忆、不建提醒、不猜截止时间。
  - 防连点：保存中按钮禁用 + 草稿关闭；保存成功后按钮换成「打开笔记」，直接跳到那条笔记。

**提取待办是独立动作**

保存与解析彻底分开：

- 「保存」只落库（离线可用，后端不可用也不影响）。
- 「提取待办」才调用 `POST /v1/extractions`，并把结果送进**确认页**：每条候选显示类型、标题、截止、原话依据、歧义提示；默认全选、可逐条取消；按钮上写着「保存所选（N）」，只有这一下会写 task / note，写完全清空候选，连点不会写两份。
- 没有关键词规则生成本地任务/提醒：截止时间只能来自服务端确定性时间解析，模型自己算出的时刻一律不用。

### 后端接通情况（结论先说）

本地起 `services/api`（`DAYCUE_LLM_*` 从 `scripts/.lan-secrets.json` 注入，未写进仓库），用 `adb reverse tcp:8787 tcp:8787` 让手机连本机：

| 检查项 | 结果 |
| --- | --- |
| `GET /v1/health` | 200，`providers:{asr:"absent", llm:"configured"}` |
| 错令牌 | 401 `unauthorized`（令牌确实在生效） |
| `POST /v1/extractions`（真实调用） | **通了 HTTP，但结果不可用**：供应商 `airelay.buzz` 的 `deepseek-v4.1-flash` 不按契约输出，返回的是 `{"intent":…,"remind_at":…}` 这种别的形状 |
| `POST /v1/transcriptions` | 503 `service_unavailable`，**缺 `DAYCUE_ASR_BASE_URL` / `DAYCUE_ASR_API_KEY` / `DAYCUE_ASR_MODEL`** |

顺手修了后端两处（都属于「不修就没法如实验收」）：

1. `newProactiveProducer` 在没有数据库时返回错误导致整个进程退出，与它自己注释里写的「没有数据库就明确不启动」矛盾；改成返回 nil（main 里本来就有判空）。
2. `normalize.go` 把「合法 JSON 但没有 `items` 数组」当成「没有可整理的事项」。这会把用户明确写下的待办说成空内容，并且把记录标成已解析。现在这种情况返回 `model_output_invalid`（502），界面显示「AI 返回的内容无法解析为结构化候选。原始记录已保留，可稍后重试」。
3. 补了 `TestNormalizeNonContractShapeIsError`，`go test ./...` 全绿。

**没有做的事（明确写出来）**：没有把供应商换成别的模型，也没有用 `DAYCUE_FIXTURE_MODE` 的样例当成功结果报给你。真实解析要能跑，需要换一个遵守 JSON 契约的模型或直连供应商；真实转写要能跑，需要上面三项 ASR 凭据。
